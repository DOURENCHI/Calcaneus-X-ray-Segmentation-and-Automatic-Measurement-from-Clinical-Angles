## 2026-10 · 按教科书口径算，角度结果与已有结果图完全不符

**现象**

按骨科教科书定义实现 Böhler 角（顶点取后关节面点 B），算出来是 **118°~168°**，
但已有结果图上印的是 **3.65°~19°**，两者差了一个数量级。

**分析**

不是算错了，是**口径不同**：

| 角度 | 教科书 | 已有结果图用的 |
|---|---|---|
| Böhler 顶点 | B（后关节面点） | **A（前突点）** |
| Gissane 两臂 | D→A、D→**B** | D→A、D→**C** |

**处理**

实现两套口径：`bohler_angle` / `gissane_angle`（对齐已有结果）和
`bohler_textbook` / `gissane_textbook`（教科书），并把差异写进 README 第 3 节。

**验证**

对齐口径后，11 例 Böhler 平均绝对误差 **0.34°**（最大 1.01°）。

**现状**

✅ 已解决。**教训**：复现他人结果时，第一步应对齐**口径**而不是对齐代码。

## 2026-10 · B 点无论用什么几何规则都还原不出来

**现象**

A / C / D 三个点都能从掩膜上边界较稳定地提取，只有 B 点（后关节面最高点）
误差高达 **23.9 px**，远超可用范围。

**分析**

试过至少三种规则，全部失败：

| 规则 | 结果 |
|---|---|
| 曲率最大处 | 偏到关节面中段 |
| 陡升终点 | 落在沟的另一侧 |
| 后关节面段最高点 | 依赖"段"的划分，不稳定 |

结论：**B 点的定义不完全由轮廓几何决定**，可能依赖阅片人对关节面边界的判断。

**处理**

不再尝试新规则。在 README 7.4 明确标注"这是本仓库最重要的已知缺口"，
并在 `demo_single_case.py` 的图上写明：**关键点用的是逐像素反推的参考位置，不是自动提取的**。

**验证**

误差表：A 6.9 / B **23.9** / C 10.2 / D 3.9 px。

**现状**

⚠️ **已知边界**。唯一解法是向数据提供方索取标注脚本——继续调几何规则是死路。

## 2026-10 · 同一个种子，两次训练指标不一样

**现象**

固定 `seed=42`，同一台机器、同一份数据、同一份代码，两次运行的最好验证 Dice 不同：
0.9318 / 0.9427 / 0.9455（三次）。**从第 1 轮起逐轮指标就不同。**

**分析**

`seed` 只能固定数据划分与参数初始化，**固定不了 GPU 上的非确定性**。
cuDNN 会自动挑选卷积算法（benchmark 模式），不同算法实现的浮点累加顺序不同，
误差逐轮累积。

**处理**

`set_seed()` 默认开启 `torch.backends.cudnn.deterministic = True`。

**验证**

| 配置 | 最好验证 Dice |
|---|---|
| 关确定性，运行 A | 0.9318 |
| 关确定性，运行 B | 0.9427 |
| 关确定性，运行 C | 0.9455 |
| **开确定性，运行 D** | **0.9461** |
| **开确定性，运行 E** | **0.9461**（与 D **bit 级一致**，`0.9461320241292318`） |

**现状**

✅ 已解决，但带来一个副作用：仓库 `results/` 里记录的是**开启确定性之前**的运行 A，
而 `run_all.py` 重跑得到的是运行 D，**两者数字不逐位相同**。

这不是 bug，已在 README 7.5 和 `run_all.py` 的说明里写清楚。
**这个 1.4 个点的漂移，比任何模型改动能带来的提升都大**——它本身就说明了
"在 11 例规模上谈论 Dice 是 0.93 还是 0.94 没有意义"。

## 2026-10 · 留一验证发现 2 折完全崩溃

**现象**

11 折留一，`#31` 的 Dice = **0.3598**、`#73` = **0.3333**，其余折都在 0.90 以上。

**分析**

看预测前景占比：两折冲到 **63.8% / 68.2%**，而 GT 只有 14%——
模型退化成**"全前景"**，面积比 4.5 / 4.7。

这与 8/3 训练里"第 10–15 轮验证 Dice 塌到 0"（退化成**全背景**）
是同一类现象的两个方向：两类不平衡数据上，BCE 容易把模型推向某一端。

**关键判断**：崩溃是「种子依赖」还是「样本依赖」？

用 `--only 31,73 --repeats 3` 换种子重跑：

| 测试例 | seed=42 | seed=1042 | seed=2042 |
|---|---|---|---|
| #31 | **0.3598** | 0.8343 | 0.9635 |
| #73 | **0.3333** | 0.9505 | 0.9418 |

同一例换个种子能从 0.33 变成 0.96 ⇒ **崩溃是训练不稳定的一次随机落点**，
不是"这两例特别难"。

**处理**

改用 `BCE + Dice` 混合损失（`0.5×BCE + 0.5×soft-Dice`），
同种子、同划分，唯一变量是损失函数：

| 配置 | #31 | #73 | 面积比 |
|---|---|---|---|
| BCE | 0.3598 | 0.3333 | 4.54 / 4.75 |
| BCE + Dice | **0.8827** | **0.9536** | 1.15 / 1.07 |

**验证**

11 折标准差从 **0.2414 降到 0.0253**（缩小约 10 倍），最小值从 0.3333 抬到 0.8827。

**现状**

✅ 已量化并缓解。**正确表述**：「混合损失降低了训练崩溃的概率，使结果不再对种子敏感」，
**不是**「混合损失更准」——对照里 BCE 换种子也能到 0.94~0.96。

## 2026-10 · 8/3 划分的结论被留一验证推翻

**现象**

8/3 划分时，验证集（1、13、94）的 Dice 是 0.9631 / 0.8814 / 0.9510，
看上去"除了一例失败都很好"。

**分析**

留一验证里，这三例的 Dice 是 **0.9677 / 0.9129 / 0.9611** ——
恰好都抽到了不崩溃的种子。

**那次划分运气好，恰好没抽到崩溃折**。用 3 例当验证集，报出来的数字
本质上是"这一次抽签的结果"。

**处理**

不再以 8/3 划分的数字作为主要结论，改用留一的**分布**
（均值 ± 标准差 / 中位数 / 四分位 / 最小值）。

**验证**

留一给出了 11 例的完整分布，能看出 6/11 折 Dice < 0.95（BCE 配置）。

**现状**

⚠️ **口径已修正，但样本量问题没解决**。留一只是把"运气"这个因素量化了，
**仍然不是泛化性能**。而且留一每折用 10 例训练、8/3 只用 8 例，**两者不能直接比大小**。

## 2026-10 · 误差到底来自分割还是提点？——归因实验推翻了原先的假设

**现象**

7.3 节算出"分割边界平均偏 1.56 px，传导出角度误差 ±2~4°"，
看上去只要提升分割精度就能改善角度。

**分析**

但那个结论里混着两个误差源：**提点规则的误差**和**掩膜边界的误差**。
不拆开就没法回答"下一步该优化哪里"。

**处理**

设计 3 支线因子实验（人工/预测掩膜 × 参考/自动提点），用两条减法拆开。

**原计划是 4 支线，实际只能到 3 支线** —— 第 4 条「预测掩膜 + 参考提点」是**退化的**：
角度只由关键点坐标决定，关键点固定在参考位置后，掩膜就完全不影响结果，
那一格必然恒等于 A1。写成 4 格会在答辩时被问倒。

**验证**

| 角度 | 提点规则误差 | 分割边界误差 |
|---|---|---|
| Böhler | **6.19°**（中位 4.27） | 4.90°（中位 1.41） |
| Gissane | **13.37°**（中位 8.07） | 6.17°（中位 2.43） |

**结论与原先假设相反**：最大误差源是**提点规则**，不是分割边界。
按中位数看差 3 倍以上。

**现状**

✅ 已归因。这一条直接回答了"要不要继续优化分割"这个方向问题：
**继续提升分割精度对角度结果没有意义**，唯一解法是拿到 B 点的定义规则。

与 7.3 的交叉印证：7.3 用「敏感度 × 边界偏移」独立折算得到中位量级 1.41° / 2.43°，
两种完全独立的方法**得到同量级结果**，互相印证。

## 2026-10 · 自训模型比数据包自带掩膜好？——优势在噪声量级内

**现象**

同一次运行下把两份掩膜都和人工 GT 比：

| | 合并 IoU | 合并 Dice | 第 13 例 IoU |
|---|---|---|---|
| 数据包自带掩膜 | 0.9275 | 0.9624 | **0.9274** |
| 本项目自训 U-Net | **0.9445** | **0.9715** | 0.7880 |

整体上自训模型 IoU 高 0.017，但第 13 例明显更差。

**分析**

结合"同种子指标漂移 0.3 个点（约 0.3%）"这一事实：**+0.017 的 IoU 优势与运行噪声同量级**，
不足以支撑"我的模型比它强"这个结论。

第 13 例更差的原因：该例前景占比 **16%**，是全库最高，而训练集里最大只有 14.93%
——属于**训练分布外**的样本。

**处理**

两条一起说：**整体上略好，但第 13 例明显更差**。
表述改为「两者水平相当，且各有更差/更好的案例」。

**验证**

第 13 例的完整解剖见 `docs/case13_failure_analysis.md`（三色叠加、上边界曲线、逐列偏差、三条假设的数据化判定）。

**现状**

⚠️ **口径已修正**。这条例子的价值在于：它示范了"不要用比噪声还小的差异下结论"。
